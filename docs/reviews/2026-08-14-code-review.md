# Code review — 2026-08-14

Thorough code review of the full codebase (all 12 source files, committed + uncommitted halves). Produced by a dedicated review agent; every finding verified against the actual code. Ranked most severe first. Companion: `2026-08-14-architecture-review.md`.

## Ranked findings

1. **HIGH — server/index.js:257** — Server binds all interfaces, not loopback, with zero auth on any endpoint. `app.listen(PORT, ...)` (no host arg) listens on 0.0.0.0 even though the log line claims 127.0.0.1. Failure: anyone on the LAN can POST /api/generate|adjust (burn Anthropic credits), POST /api/playlist (create arbitrary playlists on the owner's Spotify account via the server-held tokens), or run /auth/login themselves and overwrite `.tokens.json` with their own account's tokens. Fix: `app.listen(PORT, "127.0.0.1", ...)`.
2. **HIGH — server/index.js:54** — Reflected XSS in the OAuth callback: `res.status(400).send(\`Spotify authorization failed: ${error}\`)` echoes the untrusted `?error=` query param; Express serves strings as text/html. A crafted link executes same-origin on :8888, giving a remote page full scripted access to the playlist/generate API. Fix: HTML-escape `error` or `res.type("text/plain").send(...)`.
3. **HIGH — server/spotify.js:302-331 + server/index.js:114-126** — Orphaned resolver workers write to an ended SSE response. If one worker's `resolveTrack` throws (401 after failed refresh — line 255 rethrows), `Promise.all` rejects, the route sends `error` and calls `res.end()`, but the other 2 workers keep calling `onProgress` → `res.write()` after end → ERR_STREAM_WRITE_AFTER_END emitted as an unhandled 'error', which can crash the process exactly when the refresh token expires mid-generate. Same shape in /api/adjust/stream. Fix: guard `sseSend` with `if (res.writableEnded) return;` and/or stop workers via a shared aborted flag on first throw.
4. **MEDIUM-HIGH — server/spotify.js:121-131 + 103-119** — Token-refresh race, no single-flight. Three concurrent workers all observing an expired `access_token` each fire `refreshAccessToken()`; with refresh-token rotation the losers post a now-invalid refresh_token (400, thrown without `.status`, so resolveTrack's catch at line 256 treats it as a search miss), and last-write-wins on `.tokens.json` can persist a stale refresh_token → silent logout. Fix: memoize the in-flight refresh promise (`refreshing ||= refreshAccessToken().finally(() => refreshing = null)`).
5. **MEDIUM — server/spotify.js:135-157 + 248-258** — No 429/Retry-After handling anywhere, and rate-limit errors are indistinguishable from "track doesn't exist". A 429 on /search is caught as a strategy failure and the track is returned `resolved: false` — **the product's headline hallucination gate silently reports rate-limiting as hallucination.** On createPlaylist a 429 fails the whole save. Fix: in `spotifyFetch`, on 429 sleep `Retry-After` seconds and retry once.
6. **MEDIUM — server/spotify.js:337-353** — Partial playlist save leaves an orphan. If `POST /playlists/{id}/items` fails after the create succeeded, the error propagates, the client shows "Couldn't press it", and each retry creates another empty playlist. Fix: on add-items failure, DELETE-follow the just-created playlist (or return the URL with a "tracks failed" warning) before rethrowing.
7. **MEDIUM — server/index.js:93-127, 135-188** — No server-side cancellation: client STOP aborts the fetch (App.jsx:309-311), but the server has no `req.on("close")`, so the Anthropic stream runs to completion and Spotify resolution runs against a dead socket. The refine flow has no AbortController at all (App.jsx:330-334) — it can't even be stopped client-side. Fix: on `req.close`, abort the curator stream and skip resolution.
8. **MEDIUM — client/src/App.jsx:89 + 451-464** — `trackId` collisions break reorder and React keys. `t.spotifyUri || artist—title`: a duplicate curated track, or two entries resolving to the same Spotify URI, gives SortableContext duplicate ids — `ids.indexOf(active.id)` moves the first occurrence, not the dragged row; React warns duplicate keys. Fix: make the id `${uri-or-name}#${i}` computed once per card, or dedupe resolved URIs server-side.
9. **MEDIUM (evals) — evals/judge.js:174-177, 232-244** — The judge's binding rule "'true' requires cited evidence" is prompt-only; the code accepts `toolUse.input.verdicts` verbatim. A `verification: "true"` with `evidence: []` is recorded without complaint — exactly the failure mode the harness exists to catch. Fix: post-validate each verdict and downgrade evidence-less "true" to "unverifiable" (logged).
10. **LOW-MEDIUM — repo hygiene** — Uncommitted halves are import-coupled: `styles.css` and `spotifyLink.js` are untracked while the files importing them (`main.jsx:4`, `App.jsx:16`) are modified-tracked. Committing the modified set without adding the new files produces a broken build at HEAD. `evals/` and `docs/` are also untracked. Fix: commit the new files together with the App/main changes in one commit.
11. **LOW — server/index.js:36,46-47** — `pendingStates` grows unboundedly and never expires; any state issued since boot is valid forever. Fix: store `state → timestamp`, evict after ~10 min.
12. **LOW — server/spotify.js:43-47** — Non-atomic token persistence: a crash mid-`writeFileSync` corrupts `.tokens.json`; `loadTokens` then silently reports logged-out. Fix: write `.tokens.json.tmp` then `fs.renameSync`.
13. **LOW — server/spotify.js:221** — Quote injection into the field-filter query: a title containing `"` malforms `artist:"…" track:"…"`; degrades to the other strategies, but strategy 1 silently never works for those. Fix: strip `"` in `buildQueries`.
14. **LOW — server/index.js:190-214** — `/api/generate` (non-stream) duplicates the stream endpoint and is called by nothing — pure drift risk. Fix: delete it or fold both into one handler.
15. **LOW — server/curator.js:205-219 vs 233-238** — Over-length model output leaks past the clamp into SSE: `onTrack` fires uncapped while the 8-track clamp happens post-stream, so the progress log can show 9-10 rows for a card that arrives with 8. Fix: stop emitting after TRACK_COUNT.
16. **LOW — server/index.js:124, 185, 253** — Raw `err.message` (Spotify response bodies, SDK error strings) forwarded verbatim to the client. No secrets leak (verified), but needless disclosure. Fix: generic message client-side, detail in server logs.
17. **LOW (evals) — evals/judge.js:209-210, 226-228** — Failed cards are unretryable: error entries are pushed with `id`, so `done` includes them and a rerun skips instead of retrying. Fix: build `done` from entries that have `notes`.
18. **LOW (evals)** — No aggregation step: the harness produces per-note verdicts.json but nothing computes the claimed metrics (invented-rate, generic-rate, resolution-rate by category). Otherwise the harness is honest: it runs the real `generateCard`/`resolveTracks` code paths, degrades explicitly to notes-only, records `resolved` alongside verdicts, handles pause_turn correctly, and fills missing indices with an explicit "missing" verdict.
19. **INFO — client/src/App.jsx:63** — `readSSE` joins multiple `data:` lines without the spec's `\n` separator; harmless against this server (single-line JSON only) but will corrupt any future multi-line event.

## App.jsx seams (extractions that pay off — no rewrite needed)

- **a) `useSSEAction`/`streamRequest` hook:** generate (229-307), refine (316-380), and saveToSpotify (388-429) are the same skeleton three times — fetch → `!ok` JSON-error parse → readSSE with done/error capture → throw streamError → finally-reset. One hook with an event map removes ~100 duplicated lines and makes adding AbortController to refine a one-liner.
- **b) `<ProgressLog>`:** the generate console (557-587) and refine console (701-726) are near-identical markup; one component with `{lines, stage}` props.
- **c) `<MixtapeCard>`:** the sleeve (598-668) is a pure render of `{card, editable, adjusting, handlers}`.
- **d) `TrackRow.jsx`:** move TrackRow + `trackId` + the dnd wiring alongside spotifyLink.js.
- **e) `useSpotifyAuth`** for the status fetch (216-221).

Dead/inconsistent bits: `index.html` `<title>` is hard-coded to BRANDS[0] while the dev switcher cycles three wordmarks (dev-only nit). No dangerouslySetInnerHTML anywhere — all model output renders through JSX text nodes (checked), and unresolved-track hrefs go through encodeURIComponent (445), so the prompt-injection→DOM surface is clean.

## Overall health

Genuinely solid for a POC — the two hard problems (streaming partial tool-JSON extraction in curator.js, and the diff-merge refine with server-side index/duplicate validation mirrored by client-side edit-locking) are done carefully and correctly; the agent looked hard for a merge/reorder consistency bug and the index remap at index.js:163-170 checks out, as does the save-order-follows-drag-order chain. The real exposure is operational, not logical: the server is an unauthenticated LAN-reachable proxy for two paid/private credentials (findings 1-2), and the failure paths around Spotify auth expiry and rate limits (3-5) both risk a crash and quietly bias the one metric the product stakes its honesty on. Fixing findings 1-5 is roughly 30 lines total; the App.jsx extractions can wait until the name is picked.
